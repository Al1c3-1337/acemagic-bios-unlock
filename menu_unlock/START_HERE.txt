RX16 temporary Advanced-menu test v0.1
======================================

EXPERIMENTAL: checked against the supplied BIOS, but not yet boot-tested on
the RX16. Opening the native BIOS and saving the unlock remain unverified.

Target: Acemagic RX16 / AKN79C_H, BIOS CT_BI_AMI_RX16_AKN79C_A-004.
The tool checks the loaded Setup and AMITSE code against that exact dump.
If the checks fail, it stops before editing any menu.

Purpose
-------
AFU refused the modified ROM, and both setup_var and UMAF returned a security
violation on writes. This test instead exposes the menu in RAM and tries the
original firmware's setup browser, keeping its existing configuration handler.
This may still fail: menu visibility and permission to save are separate.

The program does not call SetVariable, flash firmware, clear TPM, change boot
order, disable write protection, reset the computer, or automatically save BIOS
settings. It writes a diagnostic log to the USB. UEFI firmware may write settings
when YOU select Save inside the BIOS interface.

Prepare
-------
1. Keep your original BIOS backup and BitLocker recovery key available.
2. If device encryption is enabled, suspend its protection before changing
   Secure Boot or entering the test environment.
3. Use a separate, empty FAT32 USB. Copy the CONTENTS of this folder onto it.
   The resulting paths must include:

     USB:\EFI\BOOT\BOOTX64.EFI
     USB:\RX16Menu.efi

   No flasher, ROM image, SREP configuration, or UMAF component is needed.
4. UEFI Secure Boot must be disabled to run this unsigned test utility. Do not
   delete or clear Secure Boot keys. If it is already disabled, leave it so.
5. Start a fresh boot and select the USB through the one-time boot menu. Do not
   run UMAF first in the same boot: this test needs the original form browser.

Run
---
1. The first screen runs checks and reads the current hide/protection values.
   Only the USB log is written at this stage.
2. If all checks pass, press U to apply the temporary menu edits.
3. Press O to try opening the original BIOS form browser.
4. If Main shows 'Setup Item Hide Control', set ONLY that setting to Disabled.
   Use the original BIOS Save Changes and Exit command, then reboot and inspect
   the ordinary BIOS. Additional menus should persist only if this save worked.
5. Leave RAM speed, voltages and 'Password protection of Runtime Variables'
   unchanged during this test. Do not load factory defaults.

If the original browser does not open
------------------------------------
Press Q, then the prompted key to return. If returned to a UEFI shell, type exit.
If the firmware boot menu offers 'Enter Setup', select it WITHOUT restarting.
The temporary changes disappear at reboot. If there is no way to enter Setup in
that same boot, do not use a reboot-to-firmware command as a workaround; return
the log instead.

If checks fail, a security violation appears, the setting is absent, or it
reverts, stop and return RX16_MENU_LOG.txt from the USB plus the exact screen
message. Do not try additional AFU switches. The log contains test results and
two setup values, not a complete variable dump or any password.

Undo and completion
-------------------
R restores the original menu definitions for this boot. Restarting also discards
these temporary menu edits. Neither action reverses settings that you manually
saved in the BIOS. If the UI hangs, a restart clears the temporary RAM edits.
After returning to normal Windows operation, restore Secure Boot to your chosen
normal setting and resume encryption protection. Do not load BIOS defaults to
restore Secure Boot.

Validation and sources
----------------------
The menu parser was tested against your original HII package and 1,500 malformed
or modified input cases. The patch edits 23 menu-definition bytes and one AMITSE
menu-table byte. No executable instructions or stored setting values are patched.
Hardware execution and successful saving have NOT been established.
